## Методология: почему 100-блочные пробы не подходят для абсолютных оценок

64 воркера + 100 блоков = pipeline не выходит на steady-state (нужно ~200+ блоков на прогрев очереди).  
Startup overhead ~4s (открытие 32 CQL-соединений) составляет 5-20% от времени пробы.  
Результат: 25M зона показывает ~22 blk/s вместо реальных ~57 blk/s = ×2.6 завышение → 129ч вместо 49ч.  
**Правильная методология**: 2000 блоков/проба + `last_blk_s` из Accum-строк (bench_hist_zones.sh).

## Рефакторинг

### pipeline.zig (546 → 518 строк)

`runHistorical` (165 строк) разбита на:
- `HistoricalConns.open()` — открывает 32 CQL-соединения
- `HistoricalConns.deinit()` — единое место очистки
- `HistoricalConns.saveArgs()` — формирует SaveArgs без дублирования
- `spawnHistoricalWorkers()` — spawn 64 воркеров
- `abortAndDrain()` — очистка при fatal error

### main.zig (223 → 195 строк)

`main()` разбита на:
- `parseCli()` → `CliArgs{from, to}`
- `openRedis()` — connect + auth + selectDb
- `readCursorBlock()` — читает LATEST_PROCESSED_BLOCK_NUMBER
- `RealtimeContext.init/deinit` — группирует 6 realtime-объектов
- `delayMs()` — nanosleep helper
- `runRealtimeLoop()` — весь realtime while-loop
