# DB Cleanup Promotion Log

Документ фиксирует отложенные операции очистки БД — те, для которых dry-run выполнен,
но реальное удаление ещё не подтверждено. Каждый раздел содержит всё необходимое
для возобновления операции в новой сессии.

## 1. Phantom rows в contracts_by_address_v2

**Статус:** DRY-RUN ВЫПОЛНЕН ✓ | РЕАЛЬНОЕ УДАЛЕНИЕ — ОТЛОЖЕНО (07-23)

### Что такое phantom rows

Строки в `eth.contracts_by_address_v2`, созданные трансформером для адресов из
CREATE-трейсов транзакций со статусом `status=0` (failed tx). Trace API Erigon (reth)
возвращает `result.address` даже когда внешняя транзакция ревертнулась. Трансформер
до версии v20 не фильтровал по статусу.

**Фикс применён:** v20 (2026-07-14) — трансформер теперь пропускает CREATE-трейсы
из tx со `status=0`. Новые phantom строки не появляются.

### Что нужно удалить

Файл с phantom строками: `~/phantom_v2.txt` на сервере 100.64.0.4.

**Происхождение phantom_v2.txt:** `find_phantom_addrs_v2` — полный скан 102M+ адресов
(31h48m40s, завершён 2026-07-20). Результат: 858 адресов с только-phantom строками +
114,749 inner-phantom строк (адреса, у которых есть как phantom-, так и real-deploy строки).

Итого в phantom_v2.txt: **115,607 адресов, 220,749 строк**.

Диапазон блоков в файле: 196,647 – 25,459,247 (только pre-v20, без realtime).

### Dry-run результат (2026-07-23, PID 3457949)

```
[phantom-delete] done: 115,607 addrs, 220,749 rows deleted, 0 failed, elapsed=1s
Phase 2: 0 ghost rows found (ожидаемо — ghost уже удалены 2026-07-13)
```

Лог: `/tmp/dryrun_phantom.log` на сервере (сохранён до следующей сессии?).

### Как запустить реальное удаление

```bash
ssh -i ~/.ssh/id_ed25519 alexey_smolyakov@100.64.0.4
nohup ~/delete_phantom_ghost \
  --pass=cassandra \
  --phantom-file=/home/alexey_smolyakov/phantom_v2.txt \
  --dry-run=false \
  > ~/delete_phantom_real_$(date +%Y%m%d).log 2>&1 &
echo $!
```

Ожидаемое время: ~1-2 минуты (Phase 1 dry-run занял 1s; real с Scylla-запросами — дольше).
Ожидаемый результат: 220,749 строк удалено, 0 ошибок.

### Верификация после удаления

```bash
# count_distinct_addrs_v3 — полный scan (27+ мин), даёт уникальные адреса
~/count_distinct_addrs_v3 --pass=cassandra --workers=64

# Ожидаемое: ~102,555,129 − 115,607 = ~102,439,522 unique addresses (примерно,
# плюс-минус новые адреса добавленные realtime с момента последнего scan)
```

### Контекст для принятия решения

**Почему удаление полезно:** phantom строки — адреса, не существующие в блокчейне
(CREATE от failed tx). Их присутствие делает таблицу contracts_by_address_v2 неточной
как source-of-truth для контрактных адресов. Финансовая система не должна их видеть.

**Почему решение отложено:** пользователь запретил удаления без явного подтверждения
на сессии 2026-07-23 (см. разговор). Данные чистые в смысле новых записей (v20
трансформер их не создаёт). Срочности нет.

**Предыдущие прецеденты удаления с подтверждением:**
- 2026-07-13: 102,640 ghost строк (tx_hash=null) удалено
- 2026-07-13: 167,164 phantom строк (первая итерация) удалено
- 2026-07-14: 614 gap-period phantom строк удалено

**Inner-phantom подробнее:** 858 «чистых» phantom адресов (никогда не деплоились успешно
в диапазоне block ≤ 25,422,000) + ~114,749 «смешанных» (есть успешные деплои, но есть
и phantom строки от failed tx). Оба типа включены в phantom_v2.txt.
