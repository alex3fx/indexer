### 1. Починен env-файл ScyllaDB (критическая ошибка)

При случайной замене `/etc/default/scylla-server` были утеряны переменные `SCYLLA_HOME` и `SCYLLA_CONF`. Без них Scylla падает с ошибкой:
```
Startup failed: Could not open file at conf/scylla.yaml
```

**Обязательное содержимое `/etc/default/scylla-server`:**
```

SCYLLA_CONF=/etc/scylla
SCYLLA_ARGS="--log-to-syslog 1 --log-to-stdout 0 --default-log-level info --network-stack posix"
```

### 4. Go loader (`gotest/loader/main.go`)

Raw CQL TCP загрузчик без gocql. Читает dump и пишет в Scylla.

```bash
cd /home/alex/lotos/task1/gotest/loader
/usr/local/go/bin/go build -buildvcs=false -o loader .

# Анализ дампа
./loader -dump=../writetest/dump_1000.bin -analyze

# Загрузка с truncate (чистый тест)
./loader -dump=../writetest/dump_1000.bin \
  -host=172.31.208.104:9142 -truncate \
  -conns=4 -pipe=64

# Sweep: -conns=0 тестирует 1,2,3,4,6,8 conns/table
./loader -dump=../writetest/dump_1000.bin -truncate -conns=0 -pipe=64
```

**Флаги:**
- `-truncate` — очистка таблиц вне измеряемого времени
- `-analyze` — только анализ дампа, без записи
- `-conns=N` — N соединений на таблицу (6 таблиц = N×6 всего)
- `-pipe=N` — pipeline depth

## Ключевой вывод: partition bottleneck

```
chunk = block_number / RAW_CHUNK_SIZE = block_number / 1000
blocks 25078197-25079196 → chunk 25078 и chunk 25079 → 2 партиции
```

При любом smp (2 или 24), во время загрузки 1000 последовательных блоков активны ТОЛЬКО 2 шарда.

### smp=24 МЕДЛЕННЕЕ smp=2 для этого workload

| Конфиг | mem/shard | ms/block | rows/s |
|--------|-----------|----------|--------|
| smp=2, tmpfs, 4GB | 2 GB/shard | **24-28ms** | 113-132k |
| smp=24, ext4, 8GB | 333 MB/shard | 34-36ms | 87-92k |
| smp=2, tmpfs, 32GB | 16 GB/shard | 39-42ms | 76-80k |

**Оптимум: smp=2 + 2GB/shard** (меньше флашей, консистентная нагрузка).

## Матрица бенчмарков (все верифицированные результаты, 1000 блоков)

| Конфиг | Инструмент | ms/block | Строк/сек | CQL errors проверены |
|--------|-----------|---------|-----------|---------------------|
| Docker smp=2, May-20, pool=32, pipe=256 | Zig2 e2e | 21.6ms | ~148k | нет |
| Native smp=24 ext4 8GB, pool=24, pipe=256 | Zig2 e2e | 21.7ms | ~148k | нет |
| Native smp=2 tmpfs 4GB, conns=4, pipe=64 | Go loader | **24-28ms** | 113-132k | **да** |
| Native smp=24 ext4 8GB, conns=4, pipe=64 | Go loader | 34-35ms | 91-92k | **да** |

**Gap между Zig2 e2e (~21.6ms) и loader (~26ms):**  
Zig2 делает fetch параллельно со save → естественные паузы между batch-write (~15-20ms/batch) позволяют Scylla компактировать. Loader пишет без пауз → больше давление на Scylla.

## Текущая конфигурация Scylla (оптимальная для теста)

```
SMP=2, memory=4G, data=tmpfs (/dev/shm/scylla/data), port=9142
```

Управление:
```bash
sudo -n /bin/systemctl stop/start scylla-server
sudo -n /usr/bin/rsync -a /tmp/file /etc/scylla.d/memory.conf   # изменить память
```

Для смены SMP — в `/etc/default/scylla-server` поменять `SCYLLA_ARGS`:
```
SCYLLA_ARGS="... --smp=2"    # smp=2
SCYLLA_ARGS="..."             # smp=24 (без --smp, default = все ядра)
```

## Для 5ms/block нужно

| Вариант | Что нужно | Реально? |
|---------|-----------|---------|
| Больше памяти | 128GB RAM → smp=32 → 4GB/shard | Нет на этой машине |
| Параллельный загрузчик | Грузить несколько disjoint chunk ranges одновременно | Да, реализуемо |
| Изменить chunk_size | chunk_size=50 → ~20 активных шардов | Несовместимо с прод-схемой |

**Production конфиг** (`input/.../compose.yml`): `--smp 32 --memory 128G` = 4GB/shard.  
Там 5ms/block реально при параллельной загрузке множества chunk-диапазонов.
